# AgentOS design context

Audience: a person operating their own private, domain-specific workspace. Primary use is doing and reviewing work, not reading a product website.

Read `docs/design/app-shell.md` for the binding header, lower-edge and widget rules; `docs/design/spatial.md` for composition selection; `docs/design/composer.md` for assistant design.

1. No marketing hero, welcome masthead, conventional footer or default page sidebar. The workspace is the product.
2. The only top header is a compact useful observation/context strip. Distinguish actual values, targets and freshness.
3. Keep a central circle and layered orbits across every profile: domain work on the inner orbit, ARMS capabilities on the outer orbit. Workbench/board/timeline views open inside contextual app windows. Use domain objects and meaningful relationships at the center. ARMS is the operating architecture, not a requirement for four navigation pages.
4. For an anchored map, equal-width rails keep the center at the viewport center. Inspectors and the assistant overlay without shifting it.
5. Widgets are varied, functional app instruments. Prefer compact readouts, timelines, readers and event rows over equal-card grids.
6. Place full forms and deeper workflows inside contextual app windows. Return to the same selection, filter, tab and scroll.
7. Lower-edge controls stay small: runtime controls left, instrument access center, recoverable assistant right. No fake state or unimplemented controls.
8. Persist layout separately from domain state. Hide is not delete. Provide restore and click/keyboard alternatives to any drag operation.
9. Use readable warm restrained typography and color in the reference; choose a domain-appropriate visual language for each custom OS. No fake metrics, neon glow or idle activity theatre.
10. Narrow layouts recompose the workspace rather than shrinking a desktop map. Respect reduced motion, focus and content clearance.

The reference is a teaching work studio. Its deterministic planner and offline state stay explicit. Design changes never activate providers or external execution.
